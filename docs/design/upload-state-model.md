# 素材选择与上传任务数据模型

## 目标

上传页只负责选择和确认待上传素材，上传记录页只负责展示已经创建的上传任务。两个页面不共享同一个 UI 状态对象，避免“文件已上传但仍可开始上传”等冲突。

## 1. 本地选择草稿 `UploadDraft`

`UploadDraft` 只存在于上传页内存，不写入数据库，也不代表已经创建上传任务。

```ts
type UploadDraftState = 'empty' | 'picking' | 'ready' | 'submitting'

interface UploadDraftItem {
  id: string
  sourcePath: string
  previewPath: string
  fileName: string
  kind: 'image' | 'video'
  mimeType: AllowedMimeType
  sizeBytes: number
}

interface UploadDraft {
  state: UploadDraftState
  items: readonly UploadDraftItem[]
  totalBytes: number
  error: string | null
}
```

约束：

- `empty`：`items.length === 0`，页面只展示素材选择入口。
- `picking`：微信素材选择器处于打开状态；如果此前已有草稿，原草稿在选择结果确认前保持不变。
- `ready`：至少有一个已校验素材，可以继续添加、删除单项、修改文件主名称或点击上传。
- `submitting`：用户已点击页面主按钮，该按钮本身就是二次确认；不再弹额外确认框。
- 草稿项没有 `uploading`、`uploaded`、`failed` 等任务状态。
- 上传任务开始交接后清空草稿，返回上传页时进入新的 `empty` 状态。

状态迁移：

```text
empty --打开选择器--> picking --选择成功--> ready
ready --继续添加--> picking --选择成功--> ready（原子合并）
ready --删除单项--> ready 或 empty
ready --点击上传--> submitting
submitting --任务已交接--> empty
submitting --创建前失败--> ready
```

### 继续添加的原子语义

“继续添加”是追加操作，并且整次追加保持原子性：

- 打开微信选择器时保留当前草稿，不提前清空。
- 用户在系统选择器中取消时，保留原草稿且不显示错误。
- 选择器的最大可选数量等于 `9 - 当前草稿数量`。
- 新选择与已有草稿合并后，全部通过数量、类型、大小、重复项和可读性校验，才一次性提交新草稿。
- 新选择无效或选择器异常时，保留旧草稿并显示安全错误文案。
- 新结果不能包含已有草稿中的同一本地文件，新结果内部也不允许重复文件。
- 删除单项只影响当前草稿；删除最后一项后回到 `empty`。
- 选择器打开期间禁用再次选择、删除和上传，防止并发选择结果互相覆盖。
- 图片和视频使用同一草稿集合，因此可以先选图片、再继续添加视频。

### 文件重命名语义

- 只允许编辑文件主名称，扩展名作为只读后缀单独展示。
- 重命名不改变 `kind`、`mimeType`、本地读取路径或缩略图路径。
- 主名称不能为空，不能是 `.`/`..`，不能包含 `/`、`\\` 或控制字符；完整文件名的 UTF-8 编码最长 255 bytes。
- 上传接口、数据库记录和历史列表使用确认后的完整名称；R2 对象键仍由服务端生成，不由用户文件名决定。

## 2. 服务端上传记录 `UploadRecord`

上传记录由服务端数据库和上传接口负责，是上传记录页唯一的任务状态来源。

```ts
type UploadRecordStatus =
  | 'uploading'
  | 'finalizing'
  | 'cancelling'
  | 'uploaded'
  | 'upload_failed'
  | 'aborted'
  | 'expired'

interface UploadRecord {
  id: string
  fileName: string
  kind: 'image' | 'video'
  sizeBytes: number
  status: UploadRecordStatus
  progress: { confirmedBytes: number; totalBytes: number; percent: number }
  failure: SafeUploadFailure | null
  createdAt: string
  updatedAt: string
}
```

数据库另外保存 `history_hidden_at`。它只允许出现在 `completed + ready` 的成功记录上，用于实现用户侧软清空；该字段不进入公开接口。

派生属性：

| 状态 | 页面文案 | 可取消 | 终态 |
| --- | --- | --- | --- |
| `uploading` | 正在上传 | 是 | 否 |
| `finalizing` | 正在写入私有存储 | 是 | 否 |
| `cancelling` | 正在取消 | 否 | 否 |
| `uploaded` | 已上传 | 否 | 是 |
| `upload_failed` | 上传失败 | 否 | 是 |
| `aborted` | 已取消 | 否 | 是 |
| `expired` | 已过期 | 否 | 是 |

失败原因只根据服务端允许公开的错误码映射为固定文案，不展示 R2 路径、对象键、令牌或原始上游错误。

## 3. 页面职责

### 上传页

- 管理昵称确认门槛。
- 调用微信选择器并校验素材。
- 展示本地缩略图、可编辑主文件名、固定扩展名、大小和右侧“移除”入口。
- 页面主按钮执行一次明确上传确认。
- 任务交接后跳转到 `/pages/history/index?watch=1`。
- 不展示上传进度和上传终态。
- 已确认昵称默认收起为身份摘要；进入修改状态后才展开输入框，更新成功后再次收起。

### 上传记录页

- 从服务端获取上传记录。
- 对所有非终态任务集中轮询。
- 显示进度、成功、失败原因和取消状态。
- 仅 `uploading`、`finalizing` 状态提供取消入口。
- 用户取消使用 `reason: 'userCancelled'`，接口响应后先显示 `cancelling`，随后轮询到 `aborted`。
- 提供“清空已上传记录”；只软隐藏 `uploaded` 记录，进行中、失败、已取消记录和 R2 素材都不受影响。

## 4. 导航和一致性

点击上传后的顺序：

1. 校验昵称和草稿。
2. 将草稿交给应用级上传服务。
3. 上传服务完成本地路径预检并锁定批次后，才向页面确认交接成功。
4. 清空上传页草稿，防止返回后重复提交。
5. 跳转上传记录页并短期监听新记录。
6. 上传服务在容量允许时先并发建立各文件的服务端任务，上传记录页以服务端记录为准，不复用上传页草稿状态。

正常进入记录页时只轮询已有非终态记录；从上传动作进入时，即使第一条服务端记录尚未出现，也会短期刷新等待，避免短暂空白被误判为“没有上传记录”。
等待期间显示“正在创建上传任务”，而不是空记录文案。如果页面跳转失败，批次仍由应用级服务继续，并提示用户从上传记录入口查看。

## 5. 边界情况决策

| 场景 | 一致行为 |
| --- | --- |
| 先选图片、后选视频 | 后一次作为“继续添加”合并到同一个草稿，不覆盖已有图片。 |
| 合并后超过 9 个文件 | 整次追加失败，不部分接收；已有草稿保持不变。 |
| 新选择中只有一个文件无效 | 整组新选择不生效，避免出现部分追加但用户不知情。 |
| 未确认昵称先选素材 | 允许形成预览草稿；点击上传时提示先确认昵称，草稿保留。 |
| 修改昵称 | 不清除素材草稿；昵称保存期间禁止提交上传。 |
| 连续点击选择/上传 | 第一次操作进入 `picking` 或 `submitting` 后立即锁定对应操作。 |
| 继续添加后取消系统选择器 | 原草稿完整保留。 |
| 继续添加结果有重复、超限、格式错误或不可读文件 | 原草稿完整保留，显示固定错误文案。 |
| 修改文件名 | 只更新主名称；扩展名、媒体类型、MIME 和本地路径保持不变。 |
| 文件名无效 | 保留上一个有效名称并提示；不会带着非法名称创建任务。 |
| 删除一个素材 | 同时更新文件数和总大小；删除最后一个后隐藏上传按钮。 |
| 素材临时路径在上传前失效 | 不创建无效上传；保留页面并要求重新选择。 |
| 服务容量已满或批次未被接收 | 不清空草稿、不跳转，显示固定创建失败提示。 |
| 点击上传后页面跳转失败 | 上传任务仍由应用级服务继续，用户可通过“上传记录”重新进入状态页。 |
| 上传中退出小程序 | 使用现有暂停与恢复机制；记录页重新打开后以服务端状态为准。 |
| 重复点击取消 | 第一条取消请求发出后立即进入 `cancelling`，隐藏取消入口。 |
| 取消与完成同时发生 | 服务端状态优先；若已经完成则显示“已上传”，不强行覆盖为失败。 |
| 取消请求失败 | 恢复服务端返回的状态并显示安全提示，允许在仍可取消时重试。 |
| 上传失败 | 记录页按公开错误码映射原因；不展示原始异常、路径或凭据。 |
| 清空已上传记录 | 仅软隐藏自己的成功记录；不删除 R2 对象，不影响非成功记录，并写入聚合审计事件。 |
| 上传页被销毁或小程序被系统回收 | 未提交草稿不持久化，需要重新选择；已交接任务可从服务端记录恢复。 |

## 6. 多文件批次的 V1 语义

- 一次最多选择 9 个文件，单个文件不超过 200 MB。
- 上传队列在未完成会话容量内并发启动文件任务；常见的两文件批次会先建立两条服务端记录，因此进入记录页即可同时看到。
- 服务端仍限制每个用户最多 5 条未完成会话。选择 6～9 个文件时，前 5 条先创建，后续条目随容量释放继续创建。
- 为避免多文件并发放大分片压力，新批次的每个文件一次只上传一个分片；服务端继续执行每用户最多 4 个并发分片的硬限制。
- 取消按钮只取消对应的服务端上传记录，不等同于取消整个本地批次；其余尚未开始的文件仍会继续。
- 如果后续产品要求“取消整个批次”或立即查看所有排队文件，需要新增服务端 `batchId` 与批次级状态，不能把本地草稿状态伪装成服务端记录。

## 7. 数据安全边界

- `sourcePath`、`previewPath` 仅用于当前设备上的上传预览和读取，不进入接口、数据库或日志。
- 上传记录不提供对象访问地址、R2 对象键、下载或分享入口。
- 取消操作使用新的幂等键，重复点击不会创建相互冲突的取消请求。
- 清空记录是历史可见性操作，不是对象删除操作；服务端按认证用户过滤，并写入清空数量审计事件。
