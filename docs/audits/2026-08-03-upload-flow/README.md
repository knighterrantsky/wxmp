# 素材上传流程审查

审查日期：2026-08-03

> 此文档记录第一轮改版。追加选择、文件重命名、并发建任务与历史清空的后续结论见 [第二轮审查](../2026-08-03-upload-flow-v2/README.md)。

证据截图：[上传完成后的上传页](./01-upload-completed.png)

## 范围和用户目标

本次仅审查从选择素材到查看上传状态的移动端流程。用户目标是：选择图片或视频、检查待上传内容、明确开始上传，并在统一的状态页查看进度、失败原因或取消上传。

## 总体判断

当前流程把“预览确认”和“上传状态”叠加在同一个列表中，同时又用弹窗和页面按钮重复确认，导致上传完成后仍显示“确认并开始上传”。建议将上传页定义为选择与预览页，将上传记录页定义为任务状态页。预览页中的主按钮本身就是二次确认，无需再弹确认框。

## 原流程步骤健康度（截图证据）

1. 选择素材：需优化。用户选完素材后立刻遇到确认弹窗，尚未充分查看文件内容。
2. 上传预览：较差。只有文件名和大小，没有缩略图，也不能单独删除误选文件。
3. 开始上传：较差。弹窗和“确认并开始上传”按钮重复承担同一确认动作。
4. 上传状态：较差。上传中和上传完成状态停留在预览页，完成后仍保留开始上传按钮，状态与动作冲突。
5. 上传记录：方向正确。已有独立记录页和进度展示，但目前没有用户取消入口，刷新范围也需要覆盖所有非终态任务。

## 主要问题

- 截图中的文件已经显示“已上传”和 100%，下方仍显示“确认并开始上传”，属于直接的状态冲突。
- 昵称已经确认后，整张昵称卡和“申请微信昵称授权”仍占据主要视觉位置，抢走了上传主任务的注意力；应收起为一行身份信息和“修改昵称”次级入口。
- “重新选择图片或视频”看起来会替换全部文件，但页面没有单文件删除入口，误选一个文件时修改成本过高。
- 文件预览缺少图片或视频缩略图，用户难以确认选择是否正确。
- 失败状态只有通用提示。应映射为安全、可行动的原因，例如网络中断、文件失效、格式不支持；不可直接展示后端原始错误。

## 已实施流程

1. 空状态上传页：显示身份摘要、选择图片或视频按钮和上传说明。
2. 预览状态上传页：显示缩略图、文件名和大小；每项提供删除按钮；“重新选择”按原子替换处理；底部主按钮显示“上传 N 个素材”。
3. 点击主按钮：直接开始上传并进入上传记录页；该按钮就是用户的二次确认，不再弹确认框。
4. 上传记录页：顶部展示进行中的任务，显示一个明确的“正在上传”状态、进度和取消按钮；取消已开始的任务时可再进行一次破坏性确认。
5. 终态记录：成功显示“已上传”，失败显示安全的失败原因，取消显示“已取消”；不再出现任何“开始上传”动作。
6. 返回上传页：已经进入上传队列的素材从预览草稿中清除，回到新的选择状态；未开始上传的预览草稿才保留。

## 可访问性注意事项

- 删除和取消不能只依赖叉号外观，需要至少 44px 左右的点击区域，并提供“移除某文件”或“取消某上传”的可读标签。
- 状态不能只靠绿色或红色表达，必须同时保留文字。
- 缩略图需要稳定尺寸，视频应带可读的“视频”标识，避免仅依赖播放图标。

## 改版后代码级健康度

1. 选择与重新选择：良好。选择器取消或新选择无效时保留原草稿；全部校验成功后才整体替换，并防止并发选择覆盖。
2. 上传预览：良好。预览列表只含本地缩略图、名称、类型、大小和移除动作，不混入上传进度或终态。
3. 开始上传：良好。页面主按钮是唯一的二次确认；只有上传服务完成预检并接收批次后才清空草稿和跳转。
4. 任务出现等待：良好。从上传动作进入记录页时短期监听新记录，等待期间显示“正在创建上传任务”，不会错误显示为空。
5. 上传状态与取消：良好。服务端记录统一展示上传、写入、取消、成功、失败和过期状态；取消有破坏性确认、乐观状态与重复请求保护。
6. 多文件批次：可用但有限。V1 顺序创建服务端任务，取消单条记录不会取消整个尚未开始的本地批次；若需要批次级取消，应新增服务端 `batchId`。
7. 昵称门槛：良好。素材可以先选；未确认昵称无法提交。已确认昵称默认收起，只有修改时展开，更新成功后再次收起。

完整状态和边界决策见 [素材选择与上传任务数据模型](../../design/upload-state-model.md)。

## 证据限制

本次只有改版前上传完成状态的单张实机截图。改版后的结论中，状态迁移和异常处理来自代码与自动化测试，不等同于实机视觉验收；微信选择器、视频缩略图、系统返回、读屏顺序、键盘昵称候选、弱网取消和不同机型点击区域仍需在开发版真机验证。
