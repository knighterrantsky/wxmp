## 目标

用户需要先后选择图片和视频，在同一预览草稿中确认缩略图、名称与数量，点击一次上传后进入记录页，同时看到每个已经接收的上传任务及其真实状态。

## 截图结论

1. 上传预览：需要调整。大号圆形叉号覆盖缩略图，视觉权重高于文件本身；“重新选择”表达整体替换，与用户继续添加媒体的心智模型不一致；文件名不可编辑。
2. 上传提交：基本正确。一个页面级“上传 N 个素材”按钮已经足够承担二次确认，不需要额外弹窗。
3. 记录出现时机：需要调整。原队列按文件串行创建服务端任务，两张图片提交后第二条记录必须等第一条完成才出现，因此看起来像同步丢失，并非历史分页丢数据。
4. 记录状态：单条记录的“上传中 0%”与服务端已建任务但尚未确认分片一致；真正的问题是同批次其他任务尚未创建，导致批次反馈不完整。
5. 历史管理：需要补充。记录页没有清理已完成记录的入口，也没有解释清理记录与删除私有素材的区别。

## 统一后的交互

- 空草稿显示“选择图片或视频”；已有草稿显示“继续添加”。图片、视频可分多次加入同一列表。
- 每一项左侧为缩略图，中部为“可编辑主名称 + 固定扩展名”，最右为低强调度文字按钮“移除”。
- 新增选择整组校验；取消、重复、超限或任一无效时，已有草稿保持不变。
- 点击“上传 N 个素材”后，在最多 5 条未完成会话的容量内并发建立服务端任务，再由记录页统一展示进度和结果。
- 上传记录中的进行中操作改成文字“取消”，避免第二个突兀的大号叉号。
- “清空已上传记录”只软隐藏成功记录，弹窗明确说明不会删除 R2 私有素材；进行中、失败、已取消记录继续保留。

## 可访问性与风险

- “移除”“取消”使用明确文字和 `aria-label`，不只依赖叉号图形；点击区域仍保持接近 44px。
- 扩展名采用只读视觉块，避免用户误以为可以把图片改成视频类型。
- 状态始终同时使用文字与颜色。
- 多文件并发只提高任务创建及时性；服务端的未完成会话和分片并发上限仍是最终约束。
- 本次截图仅覆盖 iPhone 上两个页面的单一状态。新布局、长中文名称、9 个文件、视频无缩略图、弱网暂停恢复及清空弹窗仍需用微信开发版真机复核。
